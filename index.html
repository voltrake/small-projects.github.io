The important issue is that your songs are currently stored only in this JavaScript variable: let songs = []; and when you select an MP3, you store the browser File object here: songs.push(file); That works until you refresh. After a refresh, the JavaScript starts from scratch, and the File objects are gone. Your current code does exactly this at lines 446 and 538. The solution: IndexedDB For a music player where you want the actual MP3 files to remain available after refreshing, use IndexedDB. Do not use localStorage for the MP3 files. localStorage is intended for small text data, while IndexedDB can store File/Blob objects. Your structure would become: Add MP3 ↓ File object ↓ IndexedDB ↓ Refresh page ↓ Load MP3s from IndexedDB ↓ Create object URLs ↓ Songs appear again 1. Replace your let songs = []; Change: let songs = []; let currentSong = null; to: let songs = []; let currentSong = null; const DB_NAME = "MyMusicDB"; const STORE_NAME = "songs"; 2. Add IndexedDB functions Put these functions after your variables: function openDatabase() { return new Promise((resolve, reject) => { const request = indexedDB.open(DB_NAME, 1); request.onupgradeneeded = (event) => { const db = event.target.result; if (!db.objectStoreNames.contains(STORE_NAME)) { db.createObjectStore(STORE_NAME, { keyPath: "id", autoIncrement: true }); } }; request.onsuccess = () => { resolve(request.result); }; request.onerror = () => { reject(request.error); }; }); } async function saveSong(file) { const db = await openDatabase(); return new Promise((resolve, reject) => { const transaction = db.transaction(STORE_NAME, "readwrite"); const store = transaction.objectStore(STORE_NAME); store.add({ name: file.name, file: file }); transaction.oncomplete = () => { resolve(); }; transaction.onerror = () => { reject(transaction.error); }; }); } async function loadSongs() { const db = await openDatabase(); return new Promise((resolve, reject) => { const transaction = db.transaction(STORE_NAME, "readonly"); const store = transaction.objectStore(STORE_NAME); const request = store.getAll(); request.onsuccess = () => { resolve(request.result); }; request.onerror = () => { reject(request.error); }; }); } 3. Change your file selection code You currently have: songs.push(file); at line 538. Change the whole event listener to: fileInput.addEventListener("change", async (event) => { const files = Array.from(event.target.files); for (const file of files) { if ( file.type !== "audio/mpeg" && !file.name.toLowerCase().endsWith(".mp3") ) { continue; } await saveSong(file); } await initializeMusic(); fileInput.value = ""; }); 4. Load the songs when the page starts Add this near the bottom of your JavaScript: async function initializeMusic() { songs = await loadSongs(); displaySongs(); } initializeMusic(); Now the behavior is: First visit: + Add MP3 ↓ MP3 stored in IndexedDB ↓ Song appears Refresh: Page reloads ↓ initializeMusic() ↓ IndexedDB ↓ MP3s loaded ↓ Songs appear again One important change to selectSong() Because songs will now contain objects like: { id: 1, name: "my-song.mp3", file: File } your current selectSong() needs to use .file. You currently have: const song = songs[index]; currentSong = song; const url = URL.createObjectURL(song); The relevant code is at lines 586–600. Change it to: function selectSong(index) { const song = songs[index]; if (!song) { return; } currentSong = song; const url = URL.createObjectURL(song.file); audio.src = url; songTitle.textContent = song.name; button.textContent = "▶"; progress.value = 0; currentTime.textContent = "0:00"; duration.textContent = "0:00"; displaySongs(); audio.play() .then(() => { button.textContent = "❚❚"; }) .catch(error => { console.error("Could not play audio:", error); }); } And in displaySongs(), change: if (song === currentSong) to: if (song.id === currentSong?.id) The displayed name can stay: songElement.textContent = song.name; Result With these changes, the actual MP3 files stay in that browser's IndexedDB, so refreshing the page won't remove them. One caveat: this is browser/device-specific storage. If you clear the site's browser data, use private/incognito mode, or switch to another browser/device, the songs won't be there. Also, if by "remain for myself" you mean the songs should be permanently stored in your website so every visitor gets them, that's a different solution: you'd need to upload the MP3s to a server/cloud storage rather than IndexedDB.
